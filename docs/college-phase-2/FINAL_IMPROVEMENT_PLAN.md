## Nice to have

- Small manually labeled set of difficult examples, including negation, neutral statements, sarcasm and legitimate short reviews. Report errors, not just favorable examples.
- Side-by-side “all records” and “duplicates removed” summaries with clearly stated denominators; this needs regression tests and can wait.
- Optional JSON snapshot export/import for offline transfer, with strict validation and privacy review.
- A dedicated pure showcase analysis service and smaller UI components; avoid a broad refactor immediately before presentation.
- A documented test command, explicit browser-test dependencies, and CI. This improves maintainability but is not needed to open the local demo.
- Release notes and a one-page architecture sheet. No commit/tag/release is authorized by this audit.

## Future scope

For better analytical evidence: evaluate the local engine/flagger on labeled data, record model revisions and environment, compare exact prediction vectors across batches, repeat timings, estimate confidence intervals, add a second domain, and run a user/expert study.

For cloud/automation evidence: test Docker Compose, dependency lock choices, non-root containers, model caching/readiness, direct ML input limits, trusted-proxy rate limits, bounded URL fetching, verified DB TLS, shared rate store, scoped persistence/auth tests, CI and one monitored deployment. Deployment cost and service selection require a separate decision; do not provision services during showcase preparation.

For ongoing data collection: approved source connectors, source timestamps, deduplication, queue/retry behavior, secure fetch, retention/deletion rules, sustained-load validation and human review. Multilingual inference and robust aspect analysis require separate models/data and evaluation.

## Suggested final preparation schedule

1. **Session 1, 45–60 minutes:** read the explanation and risks, run the three demo datasets, and verify title/engine/counts. Practice answering “do you detect fake reviews?”
2. **Session 2, 45 minutes:** rehearse the technical script with the anonymous college example, one known failure case, refresh/reset and export. Ask the guide to question the claims.
3. **Session 3, 30 minutes:** prepare the final slides, copy screenshots/report/CSVs to presentation media, confirm browser zoom and print layout, and freeze feature changes.
4. **Presentation day, 15 minutes early:** start the app, open the exact origin, load Product Reviews Demo, verify the output once, then reset for the live run. Keep a saved report open as fallback.

Stop adding features once this path works. The highest remaining value is explanation, rehearsal and honest evidence, not another unvalidated dashboard.
